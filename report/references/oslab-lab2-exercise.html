练习

练习

本实验围绕物理内存的发现、初始化和分配展开：内核首先选择并初始化物理内存管理器，再从设备树获取物理内存范围，由page_init()建立物理页描述符并将可用页面交给物理内存管理器；随后在理解 First-Fit 分配流程的基础上，实现并接入 Best-Fit 分配器，并通过 Buddy System 和 SLUB 扩展任务进一步理解页级分配与任意大小内存对象分配。整体实现链可以概括为pmm_init() -> init_pmm_manager() -> page_init() -> init_memmap() -> alloc_pages()/free_pages()，最终使内核能够识别、组织和分配可用物理内存。

功能模块一：物理内存初始化功能

任务一：实现物理内存探测与页描述符初始化功能（设计提示词借助 AI 完成）

要求实现的函数有：

static void page_init(void); (kern/mm/pmm.c)

功能与接口说明：根据设备树提供的物理内存信息建立可管理物理页的描述符布局，并把排除 OpenSBI、内核镜像和描述符数组占用空间后的完整空闲页面交给当前pmm_manager管理，为后续页面分配提供正确的初始状态。page_init()不接收参数也不返回结果，由pmm_init()调用；成功返回时应正确设置va_pa_offset、npage和pages，输出探测到的物理内存范围，并完成当前物理内存管理器初始空闲区的注册。

实现约束与可用资源：必须区分虚拟地址、物理地址、物理页号和Page描述符地址，正确处理可管理上界和页面对齐，并确保内核及描述符数组不会进入空闲区；设备树信息无效时应终止初始化，没有可用完整页面时不得调用init_memmap()。实现过程中可以使用get_memory_base()、get_memory_size()、panic()、cprintf()、init_memmap()、pa2page()、链接符号end、struct Page及相关全局变量，并使用框架提供的内存上界、地址转换、页面对齐和页面状态宏完成初始化。

Tips：如果对设备树中的物理内存信息、Page描述符布局或虚拟地址与物理地址之间的转换关系还不熟悉，可以先仔细阅读实验手册中“物理内存管理的设计思路”下的“物理内存探测”一节。

功能模块二：物理内存分配功能

任务一：理解first-fit 连续物理内存分配算法（思考题）

first-fit 连续物理内存分配算法作为物理内存分配一个很基础的方法，需要同学们理解它的实现过程。请大家仔细阅读实验手册的教程并结合kern/mm/default_pmm.c中的相关代码，认真阅读default_init，default_init_memmap，default_alloc_pages， default_free_pages等相关函数，并掌握程序在进行物理内存分配的过程以及各个函数的作用。

请在实验报告中结合上述函数，用自己的话简要说明 First-Fit 分配器如何初始化空闲页、分配连续物理页、回收页面并合并相邻空闲块。同时请回答如下问题：

  • 原有的first fit算法是否有进一步的改进空间？
任务二：实现 Best-Fit 连续物理内存分配算法（设计提示词借助 AI 完成）

在完成任务一后，参考kern/mm/default_pmm.c中的完整 First-Fit 实现，设计prompt，让 AI 在kern/mm/best_fit_pmm.c中标有lab2和YOUR CODE的位置实现完整的 Best-Fit 物理内存管理模块。

该文件只提供basic_check()和best_fit_check()两个测试函数，不提供具体管理函数的声明和best_fit_pmm_manager注册结构。你可以让 AI 阅读pmm.h中的struct pmm_manager，根据各成员的职责自行设计 Best-Fit 分配器的内部状态和相关管理函数，并定义best_fit_pmm_manager完成注册；生成的实现必须符合测试函数使用的状态约定，不得修改两个测试函数。算法的时空复杂度不做要求，能通过测试即可。

完成 Best-Fit 模块后，还需要在kern/mm/pmm.c的init_pmm_manager()中将当前物理内存管理器切换为best_fit_pmm_manager，否则内核运行和检查的仍是 First-Fit 实现。

任务三：buddy system（伙伴系统）分配算法（设计提示词借助 AI 完成）

Buddy System算法把系统中的可用存储空间划分为存储块(Block)来进行管理, 每个存储块的大小必须是2的n次幂(Pow(2, n)), 即1, 2, 4, 8, 16, 32, 64, 128...

请分别设计两份prompt：第一份用于让 AI 参考现有 ucore 物理内存管理框架，从零生成 Buddy System 分配模块并接入内核；第二份用于让 AI 针对第一份提示词生成的分配算法设计相应的测试函数，以检验其实现是否正确。实验不提供 Buddy System 的代码框架和测试函数，具体实现方式和测试方案由学生自行分析和描述。最终生成的模块和测试应能够正常编译运行，算法的时空复杂度不做要求，能通过测试即可。

请在实验报告中提交两份prompt，并简要说明测试覆盖了哪些核心行为和边界情况，以及这些测试为什么能够有效检验生成的 Buddy System 实现。
