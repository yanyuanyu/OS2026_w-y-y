# 提示词撰写说明核对

核对日期：2026-10-17。依据：[老师《提示词如何撰写》](references/提示词如何撰写.docx)、课程提示词说明、当前源码和已有测试。

老师建议以“可独立实现、独立验证、职责闭合的功能任务”为粒度，说明需求与成功/失败状态，使用最小可信依赖，并保留工程接口语义。四段式是推荐的组织方式；本组继续采用该结构。

| 检查点 | 当前整理结果 |
|---|---|
| 任务粒度 | 初始化、Best-Fit、Buddy 实现、Buddy 测试四个任务；每份规格内按函数描述行为 |
| PROMPT | 给出目标文件/位置、实际修改要求、修改范围、保留接口和检查函数、交付与验证结果 |
| RELY | 列出本模块所需的真实结构、宏、接口和运行前提 |
| GUARANTEE | 给出函数签名及管理器/脚本交付清单，模块辅助函数使用 static |
| SPECIFICATION | 按函数说明前置条件、成功/失败后置状态、场景和可验证要求 |
| 工程语义 | Best-Fit 精确取得 n 页；Buddy 取得 actual 页，计数按实际页数、释放沿用原 n |
| 验证与迭代 | 保留原检查、独立位图、错误路径、实际构建和 QEMU 记录，报告说明已发生的问题及解决过程 |

本次文字补充：Best-Fit 增加零页断言、成功分配首页标记、失败时页面状态保持和释放计数；初始化与 Buddy 用可检查的覆盖、状态和计数结果表达规格；Buddy 测试补充目标文件、99 退出码适配及运行结果更新条件。报告内嵌提示词与 [prompt.md](prompt.md) 中四份规格同步更新。

本次为提示词与报告整理。交付源码保持已验收的 59 个文件版本，既有真实截图和日志继续对应该版本。零页行为的补充依据实际源码的 assert(n > 0)，测试覆盖范围以相应测试和运行日志为准。
